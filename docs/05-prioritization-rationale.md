# 05 — Prioritization Rationale: ระบบยืม–คืนอุปกรณ์กีฬาและกิจกรรม (Case 08)

> ไฟล์นี้อธิบาย "ทำไม" requirement แต่ละข้อใน `05-requirement-backlog.md` จึงได้ priority ตามที่กำหนด เพื่อให้เห็นว่าการจัดลำดับไม่ใช่การเดาหรือเลือกตามความชอบส่วนตัว (สอดคล้องกับ analysis task ข้อ 5 ใน `04-requirement-candidates.md`: "จัด priority ด้วย value/risk/multi-source confirmation ไม่ใช้ความชอบส่วนบุคคล")

## 1. หลักคิด

ทีมใช้ 4 คำถามกับทุก requirement:

1. **Value:** ใครได้ประโยชน์โดยตรง และประโยชน์นั้นเกี่ยวกับ pain point หลัก (PP-01..PP-04) หรือไม่
2. **Risk:** ถ้าไม่ทำ จะเกิดข้อพิพาทความชำรุด จองซ้ำซ้อน หรืออุปกรณ์สูญหายโดยไม่มีผู้รับผิดชอบหรือไม่
3. **Urgency:** ต้องใช้ใน workflow รุ่นแรกหรือยังรอได้
4. **Dependency:** ต้องรอเกณฑ์/authority/scope decision จากผู้มีอำนาจก่อนหรือไม่

## 2. เหตุผลราย requirement

| Req ID | Priority | เหตุผลหลัก | Trade-off / Dependency |
|---|---|---|---|
| FR-EQP-01 | Must | ถ้าไม่มีการค้นประวัติแบบดิจิทัล ปัญหาหลักของ Problem Brief (ค้นประวัติยาก, PP-02) จะไม่ถูกแก้ และ requirement อื่นแทบทั้งหมดต้องพึ่งฐานข้อมูลนี้ | ต้องระบุระดับการค้น (รายอุปกรณ์/รายผู้ยืม) แต่ไม่ต้องออกแบบ UI ใน Week05 |
| FR-EQP-02 | Must | หลักฐานสภาพอุปกรณ์เป็น pain point ที่มีการยืนยันซ้ำจากสอง stakeholder (ผู้ดูแลอุปกรณ์ E-02 และผู้ยืม E-05) แก้ข้อพิพาทซึ่งเป็นความเสี่ยงสูงสุดข้อหนึ่งของโครงการ | ต้องกำหนดผู้ถ่ายภาพและสถานที่เก็บหลักฐานก่อนเขียนเป็น rule ที่สมบูรณ์ |
| FR-EQP-03 | Should | การควบคุมอุปกรณ์ราคาสูงสำคัญต่อความรับผิดชอบทางการเงิน แต่ negotiation record ระบุชัดว่ายัง Needs Validation เพราะเกณฑ์ "อุปกรณ์พิเศษ" ยังไม่ยืนยัน | ต้องมี authority matrix และเกณฑ์ราคา/รายการก่อนเขียนเป็น business rule ที่สมบูรณ์ |
| FR-EQP-04 | Should | Negotiation record ตัดสินใจ Provisional แล้วว่าให้ผู้ดูแลอุปกรณ์เป็นผู้อนุมัติการเรียกคืน (ไม่ใช่ auto-recall) แต่เกณฑ์ความเร่งด่วนและระยะเวลาแจ้งล่วงหน้ายังไม่ยืนยัน | เกณฑ์ความจำเป็นเร่งด่วนกว่า และระยะเวลาแจ้งล่วงหน้าขั้นต่ำ ต้อง hold รายละเอียด |
| FR-EQP-05 | Must | ชมรม/ผู้จัดกิจกรรมจัดอันดับปัญหาการจองซ้ำซ้อนเป็นอันดับ 1 (E-07/Q-07) และมีหลักฐานเชิงตัวเลขสนับสนุน (E-06) ความเสี่ยงสูงและ urgency สูงชัดเจนที่สุดในบรรดา RC ทั้งหมด | ต้องยืนยันว่าช่วงเวลาจองล่วงหน้า 5–7 วัน เป็นค่ามาตรฐานของทุกชมรมหรือเฉพาะกลุ่มที่สัมภาษณ์ |
| FR-EQP-06 | Could | dashboard สรุปมีคุณค่าและมาจากผู้มีอำนาจตัดสินใจสูง (เจ้าหน้าที่/ผู้บริหาร) แต่เป็น need ใหม่ที่ไม่เคยอยู่ใน scope เดิม Week 2 จึงยังไม่ควรเป็น Must จนกว่าจะยืนยันผลกระทบต่อ scope | ต้องแยกส่วนพื้นฐาน (จำนวนครั้งยืม/ประวัติชำรุด/สถานะ) ออกจากคำแนะนำจัดซื้อ/งบประมาณซึ่งใกล้เคียงกับส่วนบัญชีที่นอกขอบเขต |
| NFR-EQP-01 | Must | data minimization และการไม่เชื่อมกับระบบบัญชี/ค่าปรับเป็น boundary ที่ทีมตกลงไว้ชัดเจนตั้งแต่ Week 2 Scope Statement ไม่ใช่สมมติฐานใหม่ | ไม่มี dependency เพิ่มเติม พร้อมใช้ทำ Quality Scenario ได้ทันที |
| NFR-EQP-02 | Should | ควบคุมการเข้าถึงหลักฐานภาพถ่ายเป็นส่วนขยายที่จำเป็นของ FR-EQP-02 เพื่อป้องกันข้อพิพาทเรื่องความน่าเชื่อถือของหลักฐาน | ต้องรอผลจาก FR-EQP-02 (ใครถ่ายภาพ/เก็บที่ไหน) ก่อนกำหนดสิทธิ์การเข้าถึงแบบละเอียด |
| NFR-EQP-03 | Should | ผู้ใช้หลักเข้าถึงผ่านมือถือเป็นส่วนใหญ่ตามที่ระบุใน Problem Brief Week 1 | ยังไม่มีหลักฐานเชิงปริมาณจากการสัมภาษณ์ Week 4 มายืนยันซ้ำ |
| ISSUE-EQP-01 | Won't yet | คำแนะนำจัดซื้อ/งบประมาณเชื่อมโยงใกล้กับส่วนบัญชี/ค่าปรับที่ Week 2 Scope Statement กันไว้นอกขอบเขตอย่างชัดเจน | ต้องรอ scope owner/ผู้สอนยืนยันก่อนว่ากระทบขอบเขตเดิมหรือไม่ |

## 3. สิ่งที่ไม่ได้เลือกเป็น requirement ทันที

| สิ่งที่พบใน Week04 | เหตุผลที่ยังไม่กำหนดเป็น requirement |
|---|---|
| Auto-recall อัตโนมัติเมื่อมีคำขอแย่งอุปกรณ์ (Option C ใน Negotiation N-01) | Negotiation record ประเมินว่าความเสี่ยงสูง (ไม่มีดุลพินิจของมนุษย์) จึงเลือก Option B แทน ไม่นำ Option C มาเป็น requirement |
| ทุกคำขออนุมัติต้องผ่านผู้มีอำนาจระดับสูงเสมอ ไม่แยกระดับ (Option C ใน Negotiation N-02) | operational cost สูงเกินจำเป็นเมื่อเทียบกับ fairness ที่ได้ ทีมเลือก Option B (แยกระดับ) แทน |
| เกณฑ์ราคา/รายการที่ถือเป็น "อุปกรณ์พิเศษ" | ยังไม่มี evidence ยืนยันจากหัวหน้าศูนย์กีฬา/อาจารย์ผู้รับผิดชอบ ห้ามฟันธงเองจากสมมติฐาน |
| คำแนะนำจัดซื้อ/งบประมาณใน RC-06 | เชื่อมโยงใกล้กับส่วนบัญชีที่ Week 2 กันไว้นอกขอบเขตชัดเจน ต้องแยกออกเป็น ISSUE-EQP-01 |
| การชดเชยผู้ยืมเดิมเมื่อถูกเรียกคืนก่อนกำหนด | ไม่มี evidence รองรับรูปแบบการชดเชยที่ชัดเจน ยังเป็นเพียง unresolved item ใน Negotiation N-01 |
| รายละเอียดผู้ถ่ายภาพ/สถานที่เก็บหลักฐาน (RC-02) | Evidence ยืนยันเฉพาะ "ต้องมีหลักฐาน" แต่ยังไม่ยืนยันกระบวนการปฏิบัติจริง จึงคงไว้เป็น open question ใน FR-EQP-02 แทนที่จะเดาเอง |

## 4. บทเรียนสำหรับทีม

- Priority สูง (Must) ไม่ได้แปลว่ารายละเอียดครบแล้วเสมอไป — FR-EQP-01 และ FR-EQP-02 เป็น Must แต่ยังอยู่ในสถานะ Needs Follow-up
- Requirement ที่มาจากผู้มีอำนาจตัดสินใจสูง (เช่น RC-06 จากเจ้าหน้าที่/ผู้บริหาร) ไม่ได้แปลว่าต้องเป็น Must ทันที ถ้ายังกระทบขอบเขตเดิมที่ยังไม่ยืนยัน
- Requirement ที่ negotiation ตัดสินใจแล้ว (Provisional/Needs Validation) ยังไม่เท่ากับ Approved — ต้องคง Needs Follow-up จนกว่าจะมี evidence เพิ่ม
- Backlog ที่ดีช่วยบอกว่า "ทำอะไรต่อได้ (Week06)" และ "อะไรยังไม่ควรเดา (ISSUE-EQP-01 และ open questions)"
