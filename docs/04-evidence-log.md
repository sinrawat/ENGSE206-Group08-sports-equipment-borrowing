## 3. How the Team Derived Needs

| Evidence | ทำไมถือเป็น Need/Constraint | Need ที่ได้ |

| E-02, E-05 | ทั้งฝั่งผู้ดูแลอุปกรณ์และผู้ยืมพูดถึงปัญหาเดียวกันคือไม่มีหลักฐานสภาพอุปกรณ์ ความสอดคล้องข้าม stakeholder ทำให้มั่นใจว่าเป็น need จริง ไม่ใช่ความเห็นส่วนตัว | N-02 ทั้งสองฝ่ายต้องการหลักฐานสภาพอุปกรณ์ก่อน–หลังยืมที่ตรวจสอบได้ |
| E-03 | มีการระบุขอบเขตอำนาจอนุมัติที่ชัดเจนเป็นเงื่อนไข ไม่ใช่ความต้องการเชิงฟีเจอร์ จึงจัดเป็น constraint ต่อ workflow | N-03 ระบบต้องรองรับการอนุมัติแบบแยกระดับตามประเภทอุปกรณ์ |
| E-04 | คำตอบยืนยันตัวเลขที่ใกล้เคียงกับ assumption เดิม (BR-03) จึงใช้ยืนยันแทนที่จะสร้าง need ใหม่ แต่มีรายละเอียดเพิ่ม (การทวงคืนก่อนกำหนด) ที่เป็น need ใหม่ | N-04 ระบบต้องรองรับการเรียกคืนอุปกรณ์ก่อนกำหนดเมื่อมีความต้องการแย่งใช้ |
| E-06, E-07 | ชมรมยืนยันทั้งตัวเลขวันจองล่วงหน้าและจัดลำดับปัญหาความรุนแรง ทำให้เห็นทั้ง fact และ priority ชัดเจน | N-05 ระบบต้องป้องกันการจองซ้ำซ้อนแบบเรียลไทม์เป็นอันดับความสำคัญสูงสุด |
| E-08 | เจ้าหน้าที่ระบุ pain point ด้าน reporting ที่ไม่เคยปรากฏใน Week 1–3 มาก่อน จึงเป็น need ใหม่ที่ต้องเพิ่มเข้า scope | N-06 เจ้าหน้าที่ต้องการรายงาน/dashboard สรุปการใช้งานและสภาพอุปกรณ์ |
