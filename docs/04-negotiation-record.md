# Week 04 — Conflict and Negotiation Record
## Case 08: ระบบยืม–คืนอุปกรณ์กีฬาและกิจกรรม | ทีม: Team 08

> **Status rule:** ผลการเจรจาในเอกสารนี้เป็น Candidate/Provisional/Unresolved เท่านั้น ไม่ใช่นโยบายจริงหรือ Approved requirement

## 1. Negotiation method

แต่ละประเด็นแยก **Position** (สิ่งที่แต่ละฝ่ายเรียกร้อง) ออกจาก **Interest** (เหตุผล/ผลลัพธ์ที่ต้องการ) ตรวจ authority/constraint แล้วเปรียบเทียบ options ด้วยเกณฑ์ร่วม ได้แก่ usability, operational effort, fairness, traceability/risk, scope และ feasibility

## 2. Negotiation register

### N-01 — สิทธิ์ผู้ยืมเดิม vs การเรียกคืนอุปกรณ์ก่อนกำหนด

| Field | Record |
|---|---|
| Evidence | E-04 |
| Position A — นักศึกษา/ผู้ยืม | ต้องการใช้อุปกรณ์จนครบกำหนดยืมตามที่ตกลงไว้ (2–3 วัน) โดยไม่ถูกเรียกคืนกะทันหัน |
| Interest A | ความคาดการณ์ได้ (predictability) และไม่กระทบแผนการใช้งานที่วางไว้ |
| Position B — ผู้ดูแลอุปกรณ์ / ชมรมที่ต้องการใช้ทรัพยากรเดียวกัน | ต้องการเรียกคืนอุปกรณ์ก่อนกำหนดได้เมื่อมีความจำเป็นเร่งด่วนกว่า |
| Interest B | ใช้ทรัพยากรที่มีจำกัดอย่างมีประสิทธิภาพ ไม่ให้กิจกรรมสำคัญขาดอุปกรณ์ |
| Authority/constraint | ยังไม่มีเกณฑ์ว่าอะไรคือ "ความจำเป็นเร่งด่วนกว่า"; ต้องยืนยันกับผู้ดูแลอุปกรณ์/หัวหน้าศูนย์กีฬาก่อน |

| Option | Description | Usability | Operational effort | Traceability/Risk |
|---|---|---:|---:|---|
| A | ไม่มีการเรียกคืนก่อนกำหนดเลย (สิทธิ์ผู้ยืมเดิมคงที่จนครบกำหนด) | Medium | Low | ปลอดภัยต่อผู้ยืม แต่แก้ปัญหาการแย่งใช้ไม่ได้ |
| B | ผู้ดูแลอุปกรณ์เป็นผู้อนุมัติการเรียกคืนก่อนกำหนด พร้อมแจ้งเหตุผลและแจ้งล่วงหน้าแก่ผู้ยืมเดิม | High | Medium | ต้องบันทึกเหตุผล/ผู้อนุมัติ/เวลาที่แจ้งเพื่อตรวจย้อนหลังได้ |
| C | ระบบเรียกคืนอัตโนมัติเมื่อมีคำขอแย่งชิงอุปกรณ์ชิ้นเดียวกัน (auto-recall) | Low | High | เสี่ยงเรียกคืนผิดกรณีและไม่มีดุลพินิจของมนุษย์ |

**Decision/status:** เลือก Option B เป็น **Provisional** เพราะให้อำนาจตัดสินใจอยู่กับผู้ดูแลอุปกรณ์ (ซึ่งมีอำนาจอนุมัติอยู่แล้วตาม E-03) แทนการ auto-recall ที่ยังไม่มีหลักฐานรองรับ  
**Rationale:** E-04 ยืนยันว่าเคยเกิดเหตุการณ์จริงและกระทบผู้ยืม แต่ยังไม่มีกฎที่ชัดเจนว่าเรียกคืนได้เมื่อใดหรือใครตัดสิน  
**Unresolved:** เกณฑ์ความจำเป็นเร่งด่วน, ระยะเวลาแจ้งล่วงหน้าขั้นต่ำ, ทางเลือก/การชดเชยให้ผู้ยืมเดิม  
**Derived candidate:** RC-04

### N-02 — อนุมัติเองของผู้ดูแลอุปกรณ์ vs การควบคุมอุปกรณ์พิเศษ/ราคาสูง

| Field | Record |
|---|---|
| Evidence | E-03 |
| Position A — ผู้ดูแลอุปกรณ์ / ชมรมผู้ขอยืม | ต้องการยืมอุปกรณ์ได้รวดเร็วโดยไม่ต้องรอการอนุมัติหลายขั้น |
| Interest A | ทันเวลาจัดกิจกรรม ลดขั้นตอนที่ไม่จำเป็น |
| Position B — เจ้าหน้าที่/ผู้บริหาร (ผู้มีอำนาจระดับสูงกว่า) | ต้องการควบคุมอุปกรณ์ราคาสูง/กิจกรรมใหญ่ไม่ให้เสียหายหรือสูญหายง่าย |
| Interest B | ความรับผิดชอบและป้องกันความเสียหายทางการเงิน |
| Authority/constraint | เกณฑ์ "อุปกรณ์พิเศษ" (ราคา/ประเภท) ยังไม่ถูกกำหนดชัดเจน ต้องยืนยันกับหัวหน้าศูนย์กีฬา/อาจารย์ผู้รับผิดชอบ |

| Option | Description | Fairness | Feasibility | Auditability |
|---|---|---:|---:|---:|
| A | ผู้ดูแลอุปกรณ์อนุมัติเองได้ทุกกรณี ไม่มีการยกระดับ | Medium | High | Low; ไม่มีการตรวจสอบสำหรับอุปกรณ์มูลค่าสูง |
| B | แยกระดับอนุมัติ — อุปกรณ์ทั่วไปอนุมัติเองได้ อุปกรณ์พิเศษ/ราคาสูงต้องส่งคำขอไปยังผู้มีอำนาจระดับสูงพร้อมหลักฐานกิจกรรมที่อนุมัติแล้ว | High | Medium | High; มี trace ของผู้อนุมัติและเหตุผล |
| C | ทุกคำขอต้องผ่านผู้มีอำนาจระดับสูงเสมอ ไม่แยกระดับ | Low | Low | High แต่ operational cost สูงเกินจำเป็น |

**Decision/status:** เลือก Option B เป็น **Needs Validation** (ยังไม่ถึงระดับ Provisional เพราะเกณฑ์หลักยังขาด)  
**Rationale:** E-03 บ่งชี้ว่ามีแนวทางสองระดับอยู่แล้วในทางปฏิบัติจริง แต่เกณฑ์ตัดสิน "อุปกรณ์พิเศษ" ยังไม่ยืนยัน จึงยังนำไปเขียนเป็น business rule ที่สมบูรณ์ไม่ได้  
**Unresolved:** เกณฑ์ราคา/รายการอุปกรณ์ที่นับเป็น "พิเศษ", SLA เวลาอนุมัติ, ผู้มีอำนาจระดับสูงคือใครกันแน่  
**Derived candidate:** RC-03

### N-03 — ความต้องการรายงานของเจ้าหน้าที่ vs ขอบเขตเดิมของระบบ

| Field | Record |
|---|---|
| Evidence | E-08 |
| Position A — เจ้าหน้าที่/ผู้บริหาร | ต้องการ dashboard สรุปข้อมูลการใช้งาน/ความชำรุด/คำแนะนำจัดซื้อจากระบบใหม่โดยตรง แทนการสรุปเองจากสมุด/Excel |
| Interest A | ลดเวลารวบรวมข้อมูลเอง วางแผนซ่อมบำรุง/จัดซื้อได้แม่นยำและทันเวลา |
| Position B — ทีมพัฒนา (scope keeper อ้างอิง Week 02 Scope Statement) | ต้องการจำกัดขอบเขตให้อยู่ในสิ่งที่ scope statement เดิมระบุไว้ (ไม่รวมบัญชี/ค่าปรับ) |
| Interest B | ควบคุม scope creep ให้โครงการยังทำสำเร็จได้ตามกำหนดเวลาของรายวิชา |
| Authority/constraint | reporting ไม่เคยถูกระบุไว้ชัดเจนใน Week 02 Scope Statement (มีเพียง "บัญชี/ค่าปรับ" ที่ถูกกันไว้นอกขอบเขตชัดเจน) ต้องตรวจสอบร่วมกับผู้สอน/scope owner |

| Option | Description | Scope fit | Operational effort | Evidence status |
|---|---|---:|---:|---|
| A | ไม่รวม reporting ใน backlog รอบนี้ เก็บเป็น future scope | High | Low | ปลอดภัยต่อ scope แต่ไม่ตอบ need ของเจ้าหน้าที่ |
| B | รวม reporting แบบพื้นฐาน (จำนวนครั้งยืม/ประวัติชำรุด/สถานะปัจจุบัน/กำหนดคืน) แต่ไม่รวมคำแนะนำจัดซื้อ/งบประมาณ | Medium | Medium | Supported at candidate level (E-08) |
| C | รวมทุกอย่างตามที่เจ้าหน้าที่ขอ รวมคำแนะนำจัดซื้อ/งบประมาณ | Low | High | เสี่ยงทับซ้อนกับส่วนบัญชีที่อยู่นอกขอบเขต |

**Decision/status:** **Unresolved** ในภาพรวม; รับได้เพียงแนวทาง Option B เฉพาะส่วนสรุปการใช้งาน/ความชำรุด/สถานะเป็น candidate เบื้องต้น ส่วนคำแนะนำจัดซื้อ/งบประมาณยังไม่สร้างเป็น RC  
**Rationale:** E-08 เป็น need จริงจากผู้มีอำนาจตัดสินใจสูง แต่คำแนะนำจัดซื้อ/งบประมาณเชื่อมโยงใกล้กับส่วนบัญชีที่ Week 02 กันไว้นอกขอบเขต จึงต้องแยกส่วนก่อนตัดสินใจ  
**Unresolved owner:** ผู้สอน/scope owner ของทีม; ต้องทบทวนใน Week 05 ก่อน prioritization  
**Derived candidate:** RC-06 (เฉพาะส่วนสรุปการใช้งาน/สถานะ; ไม่รวมคำแนะนำจัดซื้อ/งบประมาณ)
